# Отчёт: Шаг 13 — CI/CD: pexpect-скрипт для симуляции ввода в Shell ядра

Дата: 2026-11-26
Ветка: ci/qemu-headless (слита с main через merge --no-ff)
Пункт чеклиста: «CI/CD: Написание Python-скрипта на базе `pexpect`, который
внутри CI симулирует ввод команд пользователя в Shell ядра и проверяет ответы»

## 1. Постановка

Пункт этапа 13 требует автоматизировать то, что раньше делалось руками:
запуск ядра в QEMU, ввод команд в Shell и проверка ответов — целиком внутри
CI, без участия человека. Тест должен падать не только при «не собралось»,
но и при «собралось, но работает не так».

## 2. Что сделано

Фактически пункт закрыт в рамках шага 12 — скрипт
`.infrastructure/scripts/smoke_test.py` уже создан, отлажен и интегрирован в
workflow. Данный отчёт фиксирует соответствие чеклисту и сводит результаты.
Пересборки артефактов шаг не потребовал: ядро не менялось.

## 3. Архитектура решения

- `pexpect.spawn(qemu-system-riscv64 -M virt -bios none -kernel bin/kernel.bin
  -nographic, timeout=30)` — ядро в QEMU headless;
- перед каждой командой `child.expect(r"sh>\s*$")` — синхронизация по
  приглашению шелла; команда отправляется только когда приёмник готов,
  гонка «первая команда съедена» исключена структурно (без `sleep`);
- команды контрактного прогона: `info -> memtest -> usermode -> pmptest -> exit`;
- полный транскрипт пишется в `build/qemu-smoke.log` (эталонная копия на
  диске не трогается), проверки и отображение — на компактной нормализованной
  копии (`compact()`: `\r\n` -> `\n`, схлопывание дублирующихся пустых строк);
- 12 контрактных проверок — литеральные подстроки в списке `CHECKS`
  (паттерн + человеческое описание), без слоёв экранирования;
- негативные сценарии: `pexpect.TIMEOUT` (зависание; сообщение называет
  последнюю отправленную команду или «загрузку ядра»), неожиданный `EOF`
  (ядро упало раньше конца контракта), `PANIC` в транскрипте — каждый даёт
  отдельный FAIL с транскриптом в stderr;
- мета-проверка FAIL-пути: валидатор обязан уметь падать, доказывается
  намеренно ложным паттерном;
- `VERBOSE=1` (аргумент или переменная окружения) печатает полный транскрипт
  после прогона — проверка глазами и руками;
- в Makefile цель `ci-verify` вызывает скрипт через `$(DOCKER_RUN)`: на хосте
  — в контейнере, в CI (`CI` выставлена, `DOCKER_RUN` пуст) — нативно.

## 4. Эволюция решения

| Итерация | Что проверяла | Что вскрыла |
|----------|---------------|-------------|
| `test-mmu` (grep по логу) | факт загрузки: строки Sv39 + отсутствие PANIC | «вера на слово»: всё после строк MMU не проверялось |
| shell-версия (printf в пайп) | полный контракт из 12 подстрок | валидатор был мёртв: FAIL-ветка не срабатывала никогда |
| `ci-verify` (pexpect) | полный контракт + интерактивная синхронизация | класс проблем «гонка + экранирование» устранён структурно |

## 5. Найденные и устранённые баги

1. **Мёртвая мета-проверка.** Проверка валидатора выполнялась до создания
   лога; `grep: No such file or directory` гасился и интерпретировался как
   успех — мета-проверка всегда зелёная независимо от живости валидатора.
   Устранено: проверка только по живому транскрипту.
2. **Пустой паттерн валидатора.** В shell-версии `$$1` (make) -> `$1`
   раскрывался внешним `sh -c` в пустоту; внутренний sh получал
   `grep -q ""` — пустой паттерн матчит любую строку. FAIL-ветка не
   срабатывала ни разу. Доказано экспериментом: намеренная ошибка
   `check 'UART32'` прошла проверку. Устранено миграцией валидатора в
   Python (литеральные строки).
3. **Съеденная первая команда.** `printf` выгружал байты в пайп до готовности
   RX-обработчика ядра; в транскрипте было `sh> nfo` — потеря была незаметна,
   т.к. ни один check не ссылался на вывод `info`. Устранено синхронизацией
   pexpect по `sh>`; добавлен контрактный check на ответ `info` (`UART0`) —
   потеря теперь красный тест.

## 6. Верификация

- Локальный прогон `make ci-verify VERBOSE=1`: 12/12 контрактов,
  мета-проверка зелёная, транскрипт полный и компактный.
- Доказательство FAIL-пути: намеренно ложный паттерн даёт
  `[CI] FAIL: ...` с транскриптом и exit-кодом 1.
- CI-прогон (act): checkout -> gitleaks -> clang-format -> cppcheck ->
  clang-tidy -> build -> smoke test -> артефакт опубликован. Job succeeded.
- Merge-коммит оставляет ответвление ветки в истории
  (`git merge --no-ff`).

## 7. Формулировка для чеклиста

Первая shell-версия теста вскрыла три бага валидатора (мёртвая
мета-проверка, пустой паттерн, гонка первой команды); финальная версия на
pexpect устранила их структурно, а не точечно.

## 8. Ключевой вывод шага

Тест — это множество утверждений, и он силён ровно настолько, насколько
сильно сильнейшее из них, включая собственный FAIL-путь. Симуляция ввода
пользователя через pexpect превратила CI-проверку из «ядро не упало при
старте» в полноценный контрактный тест интерфейса ядра: команды подаются
только тогда, когда Shell готов их принять, а каждый ответ сверяется с
контрактом.
