# HOWTO: Шаг 12 — Headless smoke-тест ядра в QEMU (CI)

## 1. Цель шага

Добавить в CI-конвейер функциональный тест ядра: ядро собирается, запускается в
QEMU без графики (headless), проходит контрактный сценарий в шелле, а валидатор
проверяет полный текст транскрипта. Тест падает не только при «не собралось»,
но и при «собралось, но работает не так».

## 2. Архитектура теста

- Ядро запускается в QEMU (`qemu-system-riscv64 -M virt -bios none -nographic`).
- Python-скрипт (pexpect) интерактивно ведёт диалог с шеллом ядра:
  перед каждой командой ожидается приглашение `sh>` — гонки «команда пришла
  раньше приёмника UART» исключены структурно, без `sleep`.
- Прогон: `info -> memtest -> usermode -> pmptest -> exit`.
- Полный транскрипт сохраняется в `build/qemu-smoke.log` (эталонная копия,
  не трогаем; для отображения нормализуем переносы отдельной функцией).
- Валидатор проверяет 12 контрактных подстрок, отсутствие PANIC и живость
  собственного FAIL-пути.

## 3. Состав решений

### 3.1 Docker-образ
`qemu-system-misc` установлен заранее (ещё при создании образа) — шаг не
потребовал пересборки образа. `python3-pexpect` там же с самого начала.

### 3.2 Makefile

    VERBOSE ?= 0

    ## Контрактный smoke-тест: интерактивный прогон ядра + валидация (для CI)
    ci-verify: build
        $(DOCKER_RUN) python3 .infrastructure/scripts/smoke_test.py $(VERBOSE)

- В CI переменная `CI` выставлена автоматически, `DOCKER_RUN` пуст — цель
  исполняется нативно в job-контейнере.
- На хосте цель идёт через контейнер, как и все атомарные цели.
- Ручной интерактив остаётся на хосте: `make run` / `make debug` / `make gdb`.

### 3.3 Скрипт `.infrastructure/scripts/smoke_test.py`

Ключевые решения:
- `pexpect.spawn` + `child.expect(r"sh>\s*$")` перед каждой `sendline` —
  синхронизация по приглашению шелла;
- проверяемые строки — литералы в списке `CHECKS` (подстрока + человеческое
  описание), без трёх слоёв экранирования;
- явные негативные сценарии: `pexpect.TIMEOUT` (ядро повисло — называется
  последняя выполненная команда или «загрузка ядра») и неожиданный `EOF`
  (ядро упало раньше конца контракта) — оба с транскриптом в stderr;
- `compact()` нормализует `\r\n` и схлопывает дубли пустых строк только для
  отображения и проверок; файл-лог на диске остаётся нетронутым;
- `VERBOSE` (аргумент или переменная окружения, `=1`) печатает полный
  транскрипт после прогона — проверка глазами;
- транскрипт при FAIL идёт в stderr — причина видна прямо в логе джобы.

## 4. Контракт (12 проверок)

| # | Подстрока | Что подтверждает |
|---|-----------|------------------|
| 1 | `UART0` | команда `info` дошла и получила ответ (гонка RX исключена) |
| 2 | `Sv39 инициализирован` | MMU: таблицы созданы |
| 3 | `Трансляция включена` | MMU: satp активен |
| 4 | `Всего блоков: 1 \| Занято: 0 B` | heap: коалесценция до единого блока |
| 5 | `Попытка Double-Free на p3` | heap: тест безопасности дошёл |
| 6 | `kfree: Invalid/corrupted header` | heap: double-free пойман |
| 7 | `SYS_GET_TICKS вернул ненулевое время` | usermode: ecall вернул тики |
| 8 | `Процесс U-mode завершился через SYS_EXIT (код: 0)` | usermode: SYS_EXIT |
| 9 | `SECURITY] MMU Violation! Store/AMO Page Fault` | pmptest: классификация fault |
| 10 | `mtval=0x10000000` | pmptest: точный адрес нарушения |
| 11 | `Ядро устояло, управление возвращено в M-mode Shell` | pmptest: возврат в Shell |
| 12 | `Завершение работы системы` | exit: штатное завершение (не таймаут) |

Плюс негатив `PANIC` (его не должно быть) и мета-проверка FAIL-пути.

## 5. Мета-проверка FAIL-пути

Тест верен, только если умеет падать. Метод доказательства: подложить в
`CHECKS` заведомо несуществующую строку (например, `UART32`) и убедиться,
что прогон даёт `[CI] FAIL: ...` с транскриптом и exit-кодом 1. Затем вернуть.

Важно: если проверяемый паттерн попадает в шелл пустым — grep матчит всё.
Признак бага: тест зелёный даже на намеренно ложных данных.

## 6. Таблица «симптом -> решение» (этап шага)

| Симптом | Причина | Решение |
|---------|---------|---------|
| Тест всегда зелёный, в т.ч. на ложных данных | `$1` раскрывался внешним `sh -c` в пустоту; пустой grep-паттерн матчит всё | Логика валидатора — в Python-файл; проверять валидатор намеренной ошибкой |
| Мета-проверка срабатывает впустую | выполнялась до создания лога; `grep: No such file or directory` гасился `\|\|` | Проверка только по живому транскрипту после прогона |
| Первая команда съедена (`sh> nfo`) | `printf` в пайп раньше готовности RX; символ теряется | Синхронизация pexpect по `sh>` перед каждой командой |
| В VERBOSE-выводе разрыв после каждой строки | QEMU сериализует `\n` как `\r\n`, ядро дублирует пустые строки | `compact()` для отображения; файл-лог не трогаем |
| Ядро «висит» в CI 15 секунд | shell ждёт ввода — это штатный финал | Проверять строку «Завершение работы системы», а не код таймаута |

## 7. Интеграция в workflow

Шаг ставится после сборки и до публикации артефакта — сломанное ядро не должно
попасть в реестр:

    - name: Headless smoke test (kernel contract)
      run: make ci-verify

## 8. Использование

    make ci-verify              # тихий прогон (как в CI)
    make ci-verify VERBOSE=1    # + полный транскрипт после прогона
    make run                    # ручной интерактив на хосте

## 9. Границы теста (честно)

- Не проверяет тайминги планировщика (`sched` сознательно вне контракта —
  CI-среда немасштабируема по времени);
- не проверяет порядок сообщений (финальная строка `exit`-сообщения
  гарантирует, что досидели до конца);
- контракт текстовый: изменение строки в ядре должно осознанно менять тест.
